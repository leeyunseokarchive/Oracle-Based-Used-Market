# 데모 시연 절차 (평가표 기준 · 총 300점)

데모 평가는 평가표의 **9단계 시나리오 순서**대로 진행한다. 한 물품의 거래 흐름을 따라가며 각 항목을 보여주는 방식이다.

---

## 0. 사전 준비 (시연 시작 전)

```bash
docker start tp_oracle                       # Oracle 컨테이너 기동
cd tp_demo
.venv/bin/python init_db.py                  # 스키마+시드 재적재 (깨끗한 상태로 시작)
TP_DEBUG=0 .venv/bin/python app.py           # http://127.0.0.1:5000
```

- **`init_db.py`를 꼭 먼저 실행**해 시드 데이터를 초기화한다 (이전 시연 흔적 제거).
- **`TP_DEBUG=0`**으로 실행해야 오류 시 트레이스백 대신 안내 페이지가 떠서 예외처리 점수에 유리하다.
- **브라우저 창 2~3개**(또는 시크릿창)를 띄워 A·B·C를 동시에 로그인해 두면 채팅·실시간 상태변화 시연이 매끄럽다.

**등장 계정** (평가표 기준)

| 역할 | 회원번호 | 비밀번호 |
|---|---|---|
| 판매자 A | `C1` | `pw1` |
| 구매자 B | `C2` | `pw2` |
| 구매자 C | `C3` | `pw3` |
| 관리자 | `c0` | `admin` |

## 단계별 시연 절차 (총 300점)

### [단계 1] 로그인 & 상태 구분 — 20점
1. `C1`/`pw1`로 로그인 → 검색 홈 진입. **(로그인 전엔 상단바 없음 / 후엔 메뉴 등장 → 화면 구분 5점)**
2. 로그아웃 후 `c0`/`admin`으로 로그인 → **관리자는 "통계·DB 내용"만 보이고 일반 메뉴는 없음**을 보여주기. 일반회원 URL(`/items/new`)에 관리자가 접근하면 막히는 것까지 보이면 권한 구분 확실 **(15점)**. 확인 후 다시 `C1`로 로그인.

### [단계 2] 물품 등록 — 35점
3. 상단 **[물품등록]** → 제목·카테고리·가격·거래장소·상세설명 입력, **사진 3장 업로드** → 등록.
4. 등록된 물품 상세로 이동 → **입력한 7개 항목(제목/설명/카테고리/가격/장소/등록일시/판매상태) + 사진 3장이 그대로 보임** 확인 **(저장 20 + 사진 15)**.
   - DB 저장 증빙이 필요하면 관리자 **[DB 내용]** 화면에서 Item 행을 보여준다.

### [단계 3] 물품 검색 — 50점 ⭐가장 배점 큼
5. `C2`(B)로 로그인 → 검색 홈.
6. **단일 조건**: 제목에 "아이폰" 입력 → 검색 **(15점)**.
7. **AND·OR·NOT 조합** *(핵심 25점)*: 예) 카테고리="전자기기" **AND** 가격 100000~900000, 그리고 제목 NOT 체크 등으로 조합해 결과가 달라짐을 보여주기. **하단 "실행된 SQL 보기"를 펼쳐 WHERE 절의 AND/OR/NOT을 직접 보여주면 강력하다.**
8. **정렬**: 최신순 / 가격 낮은순 / 높은순 전환 **(10점)**.

### [단계 4] 구매 요청 (여러 명) — 25점
9. B가 A의 물품 상세에서 **[구매 요청하기]** → 제시 금액 + 메시지 입력 후 전송 **(금액·메시지 각각 저장 15점)**.
10. `C3`(C)로 로그인 → **같은 물품에** 다른 금액·메시지로 요청.
11. A(`C1`)로 돌아가 그 물품 상세(또는 판매 마이페이지) → **B와 C의 요청이 목록에 모두 보임** **(10점)**.

### [단계 5] 1:1 채팅 — 45점
12. B가 물품 상세에서 **[1:1 채팅하기]** → 방 생성·입장, 메시지 전송. C도 동일하게 채팅 시작 → **B-A 방과 C-A 방이 따로 생성** **(10점)**.
13. B가 같은 물품에서 **[1:1 채팅하기]를 다시 눌러도 새 방이 안 생기고 기존 방으로 입장** → 중복 미생성 시연.
14. 메시지에 **보낸사람·시간·내용·읽음여부**가 표시됨 **(15점)**. 상대가 입장하면 "안읽음→읽음"으로 바뀜.
15. 상단 **[채팅하기]** → **내가 참여한 방 목록 + 방마다 안 읽은 메시지 수 배지** 확인 **(방목록 10 + 안읽음 수 10)**.

### [단계 6] 거래 승인 → 예약 중 — 25점
16. A가 판매 마이페이지(또는 물품 상세 요청목록)에서 **B의 요청 [승인]** → **물품이 '예약 중'으로 바뀌고, C의 요청은 자동 삭제**됨 → C의 구매 마이페이지에서 사라진 것 확인 **(25점)**. (승인 직후 B-A 채팅방으로 자동 이동)

### [단계 7] 거래 완료 — 20점
17. A가 채팅방 우측 상단 또는 판매 마이페이지의 **[거래 완료 처리]** → **최종 거래 금액 입력** 후 확정 → **상태 '거래 완료'** + 금액 저장 **(상태 10 + 금액 10)**.

### [단계 8] 예약 자동 취소 (48시간 초과) — 25점  *독립 시연*
18. **예약 중 상태인 물품 하나**를 대상으로 한다(필요하면 다른 요청을 하나 더 승인해 예약중 물품을 만들어 둔다).
19. 판매 마이페이지의 **[데모] 48시간 경과시키기** 버튼 클릭 (또는 평가표 방식대로 SQL 한 줄 실행 후 새로고침):
    ```sql
    UPDATE Item SET resDateTime = SYSTIMESTAMP - NUMTODSINTERVAL(49,'HOUR')
    WHERE cno='C1' AND itemNo=<예약중 물품번호> AND sellStatus='예약 중';
    ```
20. 새로고침 → **물품이 '판매 중'으로 복귀 + 해당 예약(구매 요청)이 삭제됨** 확인 **(25점)**.

### [단계 9] 관리자 통계 — 20점
21. `c0`/`admin`으로 로그인 → **[통계]**.
22. **① 그룹 함수(ROLLUP)**: 지역·카테고리별 거래 건수와 **총 거래 금액 합계**, 소계/총계 행 **(10점)**.
23. **② 윈도우 함수**: 날짜별 요청 수·인기 순위(RANK)·누적 요청 수 **(10점)**.

## 전반 평가 — 35점 (시연 도중 자연스럽게 노출)

**예외 처리 (15점)** — 일부러 잘못된 동작을 한 번씩 보여준다:
- 물품 등록 시 **제목·가격 비우고 등록** → 빨간 안내 문구.
- 로그인 비번 틀리기 → 입력창 빨간 테두리 + 경고.
- **자기 물품에 구매 요청** / **거래 완료된 물품에 요청** → 멈춤 없이 안내 메시지.
- 없는 주소 접근 → 트레이스백이 아닌 안내 페이지(error.html).

**UI 편의성 (20점)** — 별도 시연 불필요. 목록의 표·카드 정리, 검색/정렬 버튼, 상태 배지(판매중 초록·예약중 노랑·완료 검정)가 한눈에 보이는 점이 자연히 평가된다.

## 💡 시연 팁
- 위 순서대로 **하나의 물품을 끝까지** 따라가면 단계 1~7이 매끄럽게 이어진다. 단계 8만 별도의 예약중 물품으로 보여주면 된다.
- 검색(3단계)과 통계(9단계)는 배점이 크고 **"실행된 SQL 보기" / DB 내용 화면**으로 근거를 직접 보여줄 수 있으니 꼭 펼쳐서 시연한다.
- 막히면 안 되는 부분: 시작 전 `init_db.py`로 초기화, `TP_DEBUG=0` 실행 — 이 두 가지만 지키면 안정적이다.
- 평가표 항목과 1:1로 대응되도록 짰으니, 각 단계 끝에 채점자가 [구현 여부]에 **O** 표시할 수 있도록 "방금 이 항목이 ○○점짜리입니다" 하고 짚어주면 좋다.
